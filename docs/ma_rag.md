# MA_RAG 最小融合

本分支从 `answer` 创建，在连续知识对话中接入 MA-RAG 的候选生成、分歧检索和候选排序思路。首版采用三个有引用的候选、一次证据复核、最多两条补充查询和一次最终回答。

方法参考 [From Conflict to Consensus: Boosting Medical Reasoning via Multi-Round Agentic RAG](https://arxiv.org/html/2603.03292v3)。本项目把设备问答的证据覆盖、适用条件和来源引用作为复核依据，使用现有回答模型执行各个角色。

## 启动

在项目 `.env` 中加入以下设置，然后重启服务。

```dotenv
MA_RAG_ENABLED=true
```

在具有虚拟环境的项目根目录启动。

```bash
.venv/bin/python -m rag_service serve --host 127.0.0.1 --port 8003
```

本机独立工作目录也可以复用旁边项目的虚拟环境。需先在此目录配置现有 `ANSWER_LLM_*` 或 `LLM_*` 和向量模型配置。

```bash
MA_RAG_ENABLED=true ../RAG_project/.venv/bin/python -m rag_service serve --host 127.0.0.1 --port 8003
```

进入“知识问答”，选择已发布知识库并发送问题。新建会话及后续追问均使用该流程。`MA_RAG_ENABLED` 默认 `false`，可关闭后对比原有回答。

## 一次提问的处理

1. 复用会话上下文改写问题，确定知识库、发布版本和设备筛选。
2. 首次检索后，生成三个候选，分别关注完整回答、适用条件及证据缺口。每份候选均通过现有引用校验。
3. 模型按证据支持和适用范围排列候选，并列出实质冲突、知识缺口和最多两个补查问题。可并存的原因和不同工况分别解释。
4. 有冲突或缺口时执行补查。所有查询使用同一个发布版本和设备筛选。两个补查结果交替合并，并与原证据交替排列，按知识编号和重复文本去重。
5. 使用整理后的证据和候选复核意见生成最终回答，引用再次经过程序校验。仍缺少的依据或测量信息在回答中说明。

每次完整流程最多调用回答模型五次，追问另计已有的问题改写调用。候选按顺序生成，实际等待时间由模型服务决定。初始检索无命中时直接返回知识不足。

最终证据条数沿用请求的 `top_k`。模型上下文使用现有的总计24,000字符、单条6,000字符限制，补查结果优先获得上下文空间。候选与复核意见用于组织回答，事实引用来自实际输入的已发布证据。

## 对接与核对

正常入口为 `/api/v1/chat` 和 `/api/v1/chat/sessions/{id}/messages`。应用现有配置开关即可启用，Agent使用原请求和响应结构。规则读取通过 `/rules` 获取完整适用集合，设备数值判断由Agent工具执行。

运行分析记录保存到 `RAG_DATA_DIR/ma_rag/{编号}.json`，包括本次问题、知识版本、三个候选、排序与争议、补查问题、命中编号、最终回答和失败原因。记录中的 `model_calls` 为尝试的模型调用次数。模型密钥通过现有本地配置读取。

复核或引用格式错误、检索失败和模型超时会进入既有会话失败状态。最后一轮失败可以重试，重复请求编号继续按现有会话逻辑处理。分析记录供本地核对，原始候选和内部排序存放于服务端。

## 验证

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_ma_rag.py' -v
.venv/bin/python -m unittest discover -s tests -p 'test_agent_api_contract.py' -v
```

推荐演示问题为“电机转子不平衡和电机转子不对中如何区分，请比较完整判断条件和主要原因”，随后追问“这两种情况分别需要补充哪些测量指标”。

首版验收检查正常会话入口、版本固定、补查证据进入最终上下文、引用来源、失败重试和调用预算。设备问答质量提升需要使用实际问题及标准依据进行后续对照评估。

### 本轮结果（2026-11-12）

全量130项自动测试通过，其中15项MA_RAG专属测试覆盖补查范围、证据预算、规则含义、失败重试和会话幂等。

使用内置真实16条规则Word、真实本地向量模型和已配置DeepSeek/deepseek-flash，在隔离临时库完成正常会话入口验收。最终验收五次模型调用耗时约26秒，复核认为已有证据覆盖问题，补查次数为0。此前运行也验证了两条补查执行但无新增证据的情况。

真实模型曾输出未通过引用校验的候选，该轮按失败处理，重试后流程成功。当前引用校验检查原文出处，结论与引用的语义支持由模型复核，实际问答质量仍需对照评测。本地验收记录位于 `outputs/ma-rag-live/acceptance.json`，运行产物由Git忽略。
