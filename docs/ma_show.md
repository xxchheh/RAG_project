# MA_show 冲突过程展示与演示

`MA_show` 从 `MA_RAG` 的 `112e936` 创建。在原有三个候选、一次复核、最多两次补查和一次最终回答的流程上，增加按需出现的过程展示。

## 正常使用

在项目 `.env` 中设置 `MA_RAG_ENABLED=true`，沿用已有回答模型、向量模型和数据配置，然后启动服务。

```bash
.venv/bin/python -m rag_service serve --host 127.0.0.1 --port 8000
```

进入“知识问答”，选择已发布知识库并发送问题。

- 复核未发现实质冲突时，直接显示普通回答及引用。只有证据缺口时，也沿用普通展示。
- 复核发现相同设备、相同条件下相互矛盾的主张时，出现“候选分歧与证据核对”。页面展示三个候选草稿、具体分歧、复核摘要、补查问题、命中片段和来源，随后显示最终回答。
- 候选和来源可以展开查看，过程面板可以收起。过程中每秒读取一次已保存的会话状态，刷新后继续显示进度，完成后保留在会话历史中。
- 核对失败或服务重启中断时保留失败状态，使用“重试本轮”重新执行。最终依据不足时明确显示知识不足。

候选参考顺序表达复核模型的意见。过程完成表示本轮生成结束，最终回答仍需按实际证据说明未解决的争议。展示层沿用候选的结论摘要和来源，完整分析记录保存在 `RAG_DATA_DIR/ma_rag/`。

## 两个可重复的演示案例

启动单独的演示服务。

```bash
.venv/bin/python scripts/ma_show_demo.py --port 8004
```

本机 `RAG_project-MA_show` 工作目录可复用相邻虚拟环境。

```bash
../RAG_project/.venv/bin/python scripts/ma_show_demo.py --port 8004
```

访问 `http://127.0.0.1:8004/`，选择“只读查询”，输入 `demo-read-token-123` 后连接。进入“知识问答”，页面顶部提供两个案例按钮，点击按钮后再发送。

| 案例 | 问题 | 预期展示 |
| --- | --- | --- |
| 普通回答 | 电机轴承润滑不足应该先检查什么？ | 三个候选结论一致，直接回答油脂状态、油量和污染等检查内容，附来源 |
| 冲突流程 | 电机一倍频升高，就可以直接判定转子不平衡吗？ | 一个候选把常见特征扩大为充分条件，其他候选要求补齐条件；展示分歧，补查完整演示判据，最终回答引用补查资料 |

演示页持续标注“固定候选演示 · 演示数据”。这个启动器使用人工编写的参考片段、固定向量和固定模型输出，实际执行本项目的检索、补查、证据合并、引用校验、会话保存和页面展示。候选中的过度判断用于展示复核过程。演示资料中的数值只用于该案例，通过普通参考资料存储。

演示服务使用临时数据目录，停止后自动清理。演示管理令牌为 `demo-admin-token-123`。阶段之间默认等待约1.2秒，可用 `--delay 2` 调整展示节奏。可在补查期间刷新页面，核对过程恢复；完成后可展开候选引用与命中片段，查看补查新增依据。

业务服务使用实际配置的模型和已发布资料。相同问题能否出现面板取决于本轮候选及复核结果，这两个固定案例用于稳定演示不同路径。

## 会话接口的可选展示字段

现有消息接口的请求参数保持原样。有冲突的会话轮次增加可选 `turns[i].analysis`，以下两个接口会返回保存的过程。

- `POST /api/v1/chat/sessions/{id}/messages`
- `GET /api/v1/chat/sessions/{id}`

无冲突轮次省略 `analysis`。客户端可继续读取原有 `status/result/error`。全部展示字段经过 `api_contract.ConflictAnalysis` 校验，来源沿用原有 `source` 结构。

| 字段 | 含义 |
| --- | --- |
| `status` | `processing`、`completed` 或 `failed` |
| `stage` | `conflict_detected`、`searching`、`evidence_ready`、`finalizing`、`completed` 或 `failed` |
| `candidates` | 候选编号、结论摘要及最多三条已校验引用；草稿可包含本轮正在核对的错误主张 |
| `conflicts` | 复核模型识别的实质分歧 |
| `ranking`、`review_summary` | 候选参考顺序及简要复核依据 |
| `searches` | 每条补查的问题、进度、命中数、相对首轮新增数及最多三个来源片段 |
| `new_evidence_count` | 最终回答提示词的证据池相对首轮新增条目数；实际引用见 `result.citations` |
| `model_calls` | 本轮 MA_RAG 尝试的回答模型调用次数，追问改写另计 |
| `outcome`、`error` | 展示摘要及可选错误提示 |
| `demonstration` | 仅单独启动的固定演示服务为 `true`，业务服务为 `false` |

补查之间可能重复命中同一来源，逐次新增数分别相对首轮计算。会话继续固定同一知识库、设备筛选和 `release_id`，由当前令牌访问自己的记录。

现有七个 Agent 读取接口继续执行原契约。规则格式、阈值、单位、`all/any` 和数值执行边界沿用现有约定。`POST /api/v1/chat` 继续返回原有独立回答结构。

## 本轮验证

```bash
.venv/bin/python -m unittest discover -s tests -v
```

本轮139项自动检查通过，包含现有 Agent 契约检查。固定演示检查覆盖普通回答、实时过程、过程持久保存、令牌隔离、失败重试、重启中断、知识不足及普通业务服务下的冲突展示。浏览器检查覆盖桌面、390px窄屏、补查期间刷新和历史恢复。

固定输出演示验证流程与展示行为。真实模型可能一致、分歧或引用失败，实际效果取决于问题和证据；本轮未进行识别准确率或问答质量提升的定量评测。此前真实模型流程验证记录见 [MA_RAG 最小融合](ma_rag.md)。
