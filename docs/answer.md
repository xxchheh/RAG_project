# 连续知识对话与轻量会话管理

`answer` 从 `main` 的 `7eb2e5f` 创建，采用独立工作目录开发。

## 使用

进入“知识问答”，选择已发布知识库，输入问题并发送。首次发送时自动创建会话，以首个问题的前 48 字作为标题。左侧历史列表可以切换会话，当前标题旁可以重命名或删除。

- “新对话”保留历史，开启空白会话，默认使用当前知识库最新发布版本。也可在查询范围中另选版本或设备类型。
- 每个会话独立保存知识库、设备筛选和发布版本，后续追问固定使用该版本。
- 消息、回答、引用与检索片段保存在服务端。刷新、重新打开网页或重启服务后，可以从历史列表继续。
- Enter 发送，Shift＋Enter 换行，输入法选词回车不会发送。
- 失败轮次保留。最后一轮失败可重试，服务重启中断的请求也会标记失败。
- 删除需确认，会永久删除该会话的消息及引用记录。
- 独立检索继续可用，结果不计入聊天历史。

## 保存和访问范围

会话保存在 `RAG_DATA_DIR/conversations.db`，知识库仍使用原有知识数据库。启动自动创建新表，无需手工迁移。部署备份时同时保留整个数据目录。

当前没有用户账号体系，以访问令牌的 SHA-256 摘要作为会话归属，数据库不保存原始令牌。同一令牌的使用者共享会话，不同令牌互不可见，管理令牌也不会自动读取只读令牌的会话。更换令牌后旧记录仍保留，但不能通过新令牌读取。

浏览器只记录上次打开的会话编号，消息以服务端为准。关闭浏览器后可重新连接，通过历史列表继续。上一版仅保存在 sessionStorage 的旧对话仍留在浏览器原键中，本版不自动导入。新建会话从本版开始持久保存。

归档知识库后可以查看保存的历史，继续提问会明确提示知识库不可用，不会切换到其他资料。第一版按单机单进程服务运行。

## 启动

在本工作目录配置 `.env`，回答模型沿用 `ANSWER_LLM_*`，未设置时沿用 `LLM_*`。支持现有 DeepSeek、Qwen 模型适配器。

本机可复用现有虚拟环境，从 `RAG_project-answer` 目录执行。默认数据位于本工作目录的 `data/rag_work`，与 main 分开。

```bash
../RAG_project/.venv/bin/python -m rag_service serve --host 127.0.0.1 --port 8002
../RAG_project/.venv/bin/python -m rag_service tokens
```

## 新增会话接口

采用现有 Bearer 管理令牌或只读令牌，操作范围限于当前令牌的会话。响应经 `api_contract.py` 新模型校验，旧读取接口及契约基线保持原样。

| 方法与路径 | 功能 |
| --- | --- |
| `GET /api/v1/chat/sessions` | 当前令牌的会话列表，最近更新在前 |
| `POST /api/v1/chat/sessions` | 创建会话，接收 kb_id、可选 release_id、device_type |
| `GET /api/v1/chat/sessions/{id}` | 会话完整信息、消息与引用 |
| `PATCH /api/v1/chat/sessions/{id}` | 重命名，接收 title |
| `DELETE /api/v1/chat/sessions/{id}` | 删除会话 |
| `POST /api/v1/chat/sessions/{id}/messages` | 发送或重试问题，返回保存后的完整会话 |

发送消息示例：

```json
{
  "query": "这种情况怎么处理？",
  "request_id": "调用方生成的唯一请求编号",
  "top_k": 5
}
```

重试最后一轮失败问题时增加 `retry_turn_id`，并使用新的 request_id。重复同一 request_id 不会重复生成或保存消息。存在处理中轮次时，其他发送请求返回 409。历史由服务端加载，消息接口不接受调用方替换历史和会话范围。

会话含 id、title、kb_id、release_id、device_type、创建与更新时间以及 turns。每轮含 id、request_id、query、status、result、error，状态为 pending、succeeded 或 failed。result 沿用聊天回答结构，包含回答、引用、检索片段及模型信息。生成失败时返回持久化的 failed 轮次，调用方必须检查该状态。

原 `POST /api/v1/chat` 仍可独立调用，接受可选 history，不保存会话。首次提问检索后生成，追问增加一次模型问题改写，再检索并生成。模型使用最近 6 轮、合计 12,000 字的上下文，历史用于理解问题，事实依据来自本轮固定版本的知识。

## 规则会话读取修复

规则条件保存时仅输出已设置字段，防止将未使用的比较符补成 null。会话响应采用相同方式序列化。读取和启动时兼容旧版自动补齐的空比较符，只处理会话中规则快照的这种格式问题。实际阈值、零值、条件组和引用保留，真正的重复边界仍由严格校验拒绝。

更新代码后重启 answer 服务即可修复已有会话的这类格式问题。新增回归使用内置真实 16 条规则 Word，覆盖新消息、读取、继续追问、旧快照恢复和规则语义。
