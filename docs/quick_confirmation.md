# 整份确认与自动入库

## 日常使用

左侧主要入口为“知识管理”和“检索与问答”。上传解析完成后自动进入该文档的内容确认页。

普通参考资料默认展示整份摘要，包括页数、说明块、待核对内容和当前可检索状态。无需翻完所有内容。按需点击“查看需关注内容”或“查看全部内容”，仍可核对原文、PDF页面、表格和公式。

点击“确认入库”，系统记录整份说明的确认结果，再准备索引并切换发布版本。未审核规则、待核对公式、未识别图像页以及解析器排除的目录等仍不进入检索。参考资料允许抽查后确认，不代表逐字核对，也不提升为正式诊断规则。

参考资料可在“按页排除内容”中填写 `12, 15-18`。编号是PDF物理页码或幻灯片编号；原文件、解析结果和历史版本保留。重新确认时可清空该输入，恢复这些页面的可用正文；待核对内容仍不会自动恢复为可检索正文。

专业规则仍按条目核对指标、单位、阈值及且／或条件；保存修改后点击“审核通过并生效”。不会因为确认说明而发布其他已审核但尚未生效的规则。

## 失败和历史记录

确认和入库是两步内部操作。页面在任务完成前显示处理中，只有索引与发布成功后才提示生效。失败时保留确认结果，原版本继续可用；重试使用同一审核结果，若文档被修改则要求重新核对。

“知识管理 → 历史记录”保留版本查看和恢复。恢复会创建新版本，并重置现有草稿审核状态，需确认提示后执行。“高级维护”中的批量发布用于原管理流程，会应用整个知识库已审核草稿及停用状态，日常无需使用。

## 管理接口新增能力

这些接口需要管理令牌，不改变任何 Agent 读取接口。

`POST /api/v1/admin/documents/{id}/confirm`

```json
{"expected_version": 2, "target": "description", "excluded_pages": [12, 15, 16]}
```

- `target` 为 `description` 或 `rule`；逐条规则确认需传 `rule_id`。
- `excluded_pages` 可省略，只允许普通参考资料的说明确认使用；省略沿用已有选择，传空数组清空。
- 可选 `note` 记录审核意见。
- 返回 HTTP 202，包含 `task_id` 和确认后的 `edit_version`。轮询既有 `/admin/tasks/{task_id}` 判断是否生效，202 不代表已入库。
- 同样内容已确认时不重复审核；本次只发布说明或所选的一条规则，不带出其他草稿。

`POST /api/v1/admin/documents/{id}/publish`

```json
{"expected_version": 3}
```

仅同步本份文档的已审核内容或停用状态，返回202和`task_id`。页面用于停用、恢复使用等文档级操作。已有全库 `/admin/publish`、`/admin/restore`、`/admin/reindex` 及独立审核接口保持原行为。

管理端文档列表及详情附加 `publication`，提供当前条目数、当前修订版条目数、发布版本与待处理状态。Agent 公开响应模型和固定基线不变。

## 部署

无需迁移数据库或重新解析原文件。停止旧服务，更新源码，按原命令启动，浏览器刷新页面即可。新功能读写现有草稿及发布记录；已发布历史内容不被改写。
