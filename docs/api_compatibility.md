# Agent v1 接口维护约定

本约定适用于外部 Agent 的七个读取接口，不要求冻结管理页面或内部数据结构。

## 固定边界

- 路径、方法、必填参数、参数范围、默认行为以 `docs/agent_api.md`、`rag_service/app.py` 的请求模型及契约基线为准。
- 成功响应通过 `rag_service/api_contract.py` 校验。核心字段必需，内部新增字段默认不会透出。
- 既有规则已声明的可选审核/来源元数据仍保留兼容，但不属于 Agent 必须依赖的字段；模型配置 `profile` 是展示信息，不作为业务判断依据。
- 保留原有响应形状：知识库为根数组；规则为 `rules`；检索为 `items`；详情为 `item`。不再包装 `data`。
- 业务失败保留 `detail`，新增稳定 `code`。422 的 `detail` 为校验错误数组，其他通常为字符串；调用方按 HTTP 状态和 `code` 判断，不解析提示文字。
- 无适用知识返回空数组；知识不足返回 HTTP 200 和 `insufficient_evidence`；系统错误不能伪装成空结果。

## 三种版本

- `/api/v1`：请求、响应与业务语义的接口版本。
- `release_id`：某知识库的不可变发布快照。一次任务固定此值；知识更新、停用、阈值修改创建新版本。
- `equipment-rules-v1`：规则结构、设备/指标编号、单位和派生计算约定。规则由 Agent 工具执行，不由 RAG 执行。

旧发布快照在知识库仍有效、数据未丢失时可访问。归档知识库返回 404。历史语义检索仍依赖对应模型配置；配置不可用返回错误。恢复知识版本不等于恢复运行环境或数据库。

## 如何修改

| 变更 | 处理方式 |
|---|---|
| 页面、解析、切分、索引、数据库实现优化 | 内部修改，保持边界输出和历史来源，运行契约测试 |
| 新说明、新规则或阈值调整 | 审核后发布新的知识版本，旧任务继续固定旧版 |
| 新增可选参数或响应字段 | 保留旧调用和默认行为，增加测试、更新文档并审核基线差异 |
| 删除/改名字段、改变类型或默认含义 | 新增 v2，保留 v1 的转换层，约定迁移后再停用 |
| 新指标、单位、运算符、公式变更 | 先确认 Agent 执行器能力；不兼容时使用新规则格式版本，不能静默改变 v1 |

禁止让 Agent 接收未知规则后自行猜测执行。未来扩展设备类型或规则能力应同步考虑请求校验、`capabilities`、规则格式和执行器兼容性。

## 验证与基线

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_agent_api_contract.py' -v
.venv/bin/python -m unittest discover -s tests -q
```

测试核对公开路由、请求/响应 OpenAPI、规则能力及真实 HTTP 响应（使用固定测试模型，不消耗真实 API）。同时覆盖版本固定、完整规则集、错误结构和鉴权。

基线 `tests/fixtures/agent_v1_contract.json` 是可审查的契约，包含引用到的 JSON Schema 和设备/指标能力。契约测试不能覆盖所有业务风险，涉及存储/索引时还需运行对应回归测试。基线不是数据库备份。

仓库已配置 GitHub Actions，在 push / PR 时运行契约测试（不调用真实模型）。本次仅验证本地执行；远程运行结果以 GitHub 为准。若要强制阻止不兼容合并，可在 GitHub 分支保护中将 `contract` 检查设为必需；本仓库文件不能代替远程分支保护设置。依赖升级若影响 OpenAPI，也需审核基线差异。
