# 设备诊断 Agent 系统介绍

**中文对话式设备分析与报告生成系统**  
当前版本：演示版 · 文档日期：2026 年 10 月 22 日

## 1. 一分钟了解这个系统

这套系统面向设备运维与状态分析场景。用户用中文描述要分析的设备、测点和时间范围，系统便可查询设备、读取数据、执行机理规则分析，并生成带有图表、判断依据和检维修建议的 Word 报告。用户还可以继续追问“为什么这样判断”“和上个月相比有什么变化”，或切换到另一台设备进行分析。

系统将大模型的语言理解能力与程序化的诊断工具结合起来：大模型负责理解需求、选择工具和组织回答，程序负责数据读取、指标计算、规则判定与报告中的事实填充，让分析结果能够对应到具体数值、规则编号和数据范围。

**当前版本已跑通从中文提问到 Word 报告生成的演示流程，使用固定模拟设备与数据，尚未接入真实设备平台。**

## 2. 它能帮助解决什么问题

设备分析通常需要经过查找设备、选择测点、查看指标、核对规则、整理结论和编写报告等步骤。本系统把这些步骤串联到一次连续对话中，方便运维人员、设备工程师和项目沟通人员查询、复核与展示分析结果。

| 使用需求 | 系统提供的能力 |
| --- | --- |
| 快速发起分析 | 用中文指定设备、测点和时间，无需手动组织工具参数 |
| 理解诊断依据 | 展示实际值、阈值条件、规则编号和判定结果 |
| 查看状态变化 | 计算窗口内趋势，并与前一等长时间窗口比较 |
| 保留历史异常线索 | 分别记录末次样本判定和窗口内历史规则命中 |
| 整理分析材料 | 自动生成统一结构的 Word 报告和配套分析数据 |
| 持续追问 | 在同一会话中复用已有证据，也可切换设备重新分析 |

## 3. 从一句话到一份报告

用户可以这样提出需求：

> 帮我分析 16 号机器的行走电机驱动端最近一个月的数据，生成 Word 报告。

系统的处理流程如下：

1. **理解需求**：识别设备线索、测点、时间范围，以及是否需要报告。
2. **确认对象**：查询设备；出现同名设备或多个测点时，继续询问用户。
3. **读取数据**：获取指定窗口的数据，记录请求范围、实际覆盖范围和缺失指标。
4. **执行分析**：计算指标，逐条匹配机理规则，扫描窗口内历史命中，并计算上期对比。
5. **解释结果**：结合数值和规则编号说明疑似问题、判断依据及来源中的建议措施。
6. **生成报告**：填充报告模板，校验关键内容后返回本地文件路径。

生成报告后，用户还可以继续问：

```text
为什么认为可能是轴承问题？请给出实际值和规则编号。
和前一个月相比有哪些变化？
换成 pump-25 这台水泵的驱动端，分析最近 30 天并生成报告。
```

## 4. 当前已实现的分析能力

### 设备与机理规则

系统目前配置了五类设备、共 16 条机理规则。规则覆盖轴承故障、转子不平衡、不对中、部件连接松动、联轴器磨损等演示场景。

| 设备类型 | 规则数量 |
| --- | ---: |
| 电机 | 4 |
| 联轴器 | 1 |
| 水泵 | 5 |
| 风机 | 5 |
| 齿轮箱 | 1 |
| **合计** | **16** |

规则保存了原文、来源、判断条件、机理原因与建议措施。程序按规则计算判定结果，并保留每个条件的实际值与满足情况。

### 时间、趋势与证据

- 模拟样本包含 90 天的每日特征，支持查询指定日期范围。
- 计算速度有效值、加速度有效值和峭度等指标的窗口趋势与前一等长窗口对比，并记录样本覆盖情况。
- 区分“末次样本命中了什么”和“这个时间窗口内曾经命中过什么”，保留历史命中日期与证据。
- 对缺失指标、无效单位或无法计算的比值保留数据不足信息；能够确定结果时仍按逻辑判定。
- 同时保留多条命中规则；某条规则未命中，不能据此排除相应故障。

演示时钟固定为 **2026-10-20（Asia/Shanghai）**。“最近一个月”按最近 30 天处理，对应 **2026-09-21 至 2026-10-20**，不随电脑当天日期变化。

## 5. 一个具体的演示案例

以 `motor-16` 行走电机的驱动端为例，分析窗口为 2026-09-21 至 2026-10-20，共 30 个模拟样本。

### 末次样本为什么命中轴承规则

末次样本日期为 2026-10-20，系统命中 **R001「电机滚动轴承故障」**。该规则要求以下三个条件同时满足：

| 判断条件 | 规则要求 | 末次样本实际值 | 结果 |
| --- | --- | --- | --- |
| 加速度非超额峭度 | 大于等于 3.5，且小于 4.5 | 4.0 | 满足 |
| 低频冲击值 | 大于等于 8，且小于 16 | 10.0 demo_index | 满足 |
| 峰值因子 | 加速度峰值 / 加速度有效值，大于等于 4 | 10.0 / 2.0 = 5.0 | 满足 |

因此，系统给出的结论是：**命中演示规则，疑似电机滚动轴承故障。** 用户可以查看数值与条件，复核这项判断。

### 系统还能补充哪些信息

- **持续性**：R001 在本期 30 个每日样本中均命中。
- **历史线索**：R004「电机部件连接松动」在 9 月 21 日至 9 月 27 日的 7 个样本中曾命中，但末次样本未命中。
- **上期对比**：速度有效值均值由上期的 4.000 mm/s 升至本期的 4.674 mm/s，增加约 16.85%；峭度均值保持 4.0。
- **建议来源**：系统依据 R001 的来源内容给出检查润滑油理化情况、按情况更换润滑油、严重时更换轴承等建议，供人工复核。

以上数值均来自现有模拟案例。`demo_index` 是演示指标单位，尚不能直接作为现场通用诊断尺度。

## 6. 最终交付什么

每份诊断报告包含以下八个部分：

| 报告章节 | 主要内容 |
| --- | --- |
| 01 结论摘要 | 疑似问题与分析结论 |
| 02 设备与数据范围 | 设备、测点、工况及数据时间范围 |
| 03 振动趋势 | 趋势图、指标变化与上期对比 |
| 04 时域波形 | 查询窗口内可用的模拟波形；不可用时说明 |
| 05 幅值频谱 | 查询窗口内可用的模拟频谱；不可用时说明 |
| 06 综合判定 | 逐规则条件、计算值、判定结果与历史命中 |
| 07 检维修措施 | 与命中规则对应、有来源的建议措施 |
| 08 参考源 | 规则来源、版本与演示口径说明 |

每份报告还配套保存：

- `analysis.json`：结构化分析结果，便于复核和后续程序处理。
- `report-manifest.json`：报告标识、来源模板摘要和校验结果等信息。

系统在返回报告成功之前，会校验章节结构、关键数值、规则引用、证据表、图片数量及模板页面设置。

本目录附有上述电机案例的 [Word 报告](report.docx)、[分析数据](analysis.json) 和 [报告校验清单](report-manifest.json)，可配合本介绍展示。

## 7. 系统如何实现

系统采用“大模型编排 + 专用工具执行”的结构。

| 模块 | 职责 |
| --- | --- |
| 中文对话与 Agent | 理解需求、保留会话上下文、调用工具、组织回答 |
| 设备与数据适配层 | 查询设备、定位测点、读取指定时间范围的数据 |
| 机理规则分析层 | 计算指标、执行规则、扫描历史命中、计算趋势与上期对比 |
| 报告生成层 | 复用 Word 模板，填充事实、图表、证据与来源，并执行校验 |

Agent 使用四个核心工具串联业务流程：

| 工具 | 用途 |
| --- | --- |
| `search_devices` | 根据设备编号、名称或位置查询设备 |
| `get_device_data` | 读取指定设备、测点和时间范围的数据 |
| `analyze_device` | 执行机理规则分析并计算趋势、历史命中与上期对比 |
| `generate_report` | 根据已有分析结果生成并校验 Word 报告 |

报告中的关键结论、数值、图表和条件表由程序填充。模型可选择并排列来源文档中已有的原因与措施，程序会校验其选择结果。

当前以 Python 实现，通过终端进行中文对话。模型适配层提供 DeepSeek、Qwen 和 OpenAI 的配置方式；现有真实 API 验收记录来自 DeepSeek，其余两家的适配尚未完成真实密钥在线验收。

## 8. 当前验证情况与应用边界

依据项目保存的 **2026-10-21 验证记录**：

- 30 项自动测试通过，覆盖规则正例、阈值边界、缺失数据、单位异常、零分母、日期处理和报告失败等情况。
- 16 条规则均有正例覆盖。
- 真实模型 API 演示通过了设备歧义澄清、一句话生成报告、复用证据追问和切换设备四类场景。
- 代表性电机与水泵报告已完成逐页渲染检查。

这些记录验证了当前演示流程与实现行为。现场诊断准确率、设备适用性和实际运维收益，仍需要真实数据与业务验证。

当前版本的应用范围如下：

| 项目 | 当前状态 |
| --- | --- |
| 数据来源 | 固定模拟设备与每日特征，尚未连接真实设备平台 |
| 分析对象 | 每次处理一个设备、一个测点；可在对话中切换 |
| 波形与频谱 | 独立模拟图谱片段，未用于计算规则输入特征 |
| 规则口径 | 演示规则；部分名称、指标定义和阈值仍需业务确认 |
| 输出用途 | 分析演示、证据复核与报告编制参考 |
| 现场操作 | 未实现自动停机、设备控制或工单执行 |

使用在线模型时，模型服务会收到对话和模拟设备摘要，原始波形留在本地。未来接入真实数据时，需要结合部署方式明确数据访问与传输范围。

## 9. 如何进行一次现场演示

在项目根目录使用已配置的运行环境启动：

```bash
.venv/bin/python -m diagnostic_agent chat --output reporttopeople/demo
```

建议按以下顺序展示：

1. **完整流程**：输入“帮我分析 16 号机器的行走电机驱动端最近一个月的数据，生成 Word 报告”，展示工具进度与报告文件。
2. **解释能力**：追问“为什么认为可能是轴承问题？请给出实际值和规则编号”，展示可复核的规则证据。
3. **变化分析**：追问“和前一个月相比有哪些变化”，展示上期对比和历史命中信息。
4. **设备切换**：输入“换成 pump-25 这台水泵的驱动端，分析最近 30 天并生成报告”，展示重新取数和分析。
5. **歧义澄清**：输入“分析循环水泵，生成报告”，展示系统对同名设备和不同测点的确认过程。

## 10. 后续扩展方向

在现有演示基础上，后续可逐步开展：

1. **接入真实数据**：替换数据适配层，对接设备台账、测点和历史指标。
2. **验证诊断规则**：由业务专家确认规则定义、阈值和适用工况，并用真实案例评估。
3. **补齐信号分析**：建立真实波形、频谱和特征计算之间的可追溯关系。
4. **完善使用入口**：根据实际用户需要增加网页界面、报告管理和权限控制。
5. **衔接运维流程**：在人工确认机制下，逐步对接工单与检维修记录。

上述内容为后续规划，尚未作为当前版本功能交付。
